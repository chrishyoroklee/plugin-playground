# Turn devices into presets, not plugins

Plugin Playground should build the unified product as two fixed, signed plugins (one effect, one instrument) whose host parameter list is frozen forever, and treat every device as a small data file that those plugins load, in this order: first prove the current plugins in real DAWs, then ship the unified effect plugin on macOS with a notarized installer and a Download tab, then add the Windows window, the instrument, macros and lock modes, and only then add sound-design assistance. The research supports this on every front. The best-reviewed all-in-one plugins look like what the project already has: a short row of modules in signal order with four or fewer controls each, a handful of macros, and a persistent strip for presets and levels. No plugin format or DAW handles a changing parameter count reliably, and every shipping modular plugin found uses a fixed list. WebView2 is workable on Windows through one header library, while Linux web view embedding remains hazardous enough to defer. AI help needs no project-paid inference, because the task is a 1 to 3 KB settings object that a keyword table, the user's own chatbot, Chrome's built-in model or the user's own OpenRouter credit can produce. Trusted distribution costs 99 USD a year on macOS and is effectively mandatory there; on Windows no purchase removes the SmartScreen warning on day one. The largest open risk is not in any of these plans: the project's own README records that nobody has yet loaded a generated plugin in a DAW.

Throughout, paragraphs marked **Established** report what the notes sourced, **Recommended** marks this report's judgment, and **Thin evidence** marks what was unconfirmed. No hands-on testing was done in any research strand.

## The best-reviewed layouts show seven tiles, four macros and no frozen play mode

**Established.** Neural DSP's Archetype X plugins present a fixed left-to-right signal chain as a short row of section icons (Pre FX, Amp, Cab, EQ, Post FX) with a persistent global strip for presets, input, output, gate, transpose, doubler and tuner ([Sound On Sound](https://www.soundonsound.com/reviews/neural-dsp-archetype-john-mayer-x)). The chain is not reorderable: only on/off and the choice within a section vary. Reviewers call the layout "well signposted and easy to find"; the one recurring complaint is that the range of effects is "a little overwhelming" when deciding where to start ([Guitar World](https://www.guitarworld.com/gear/plugins-apps/neural-dsp-archetype-misha-mansoor-x)). The X generation later retrofitted drag-to-resize, a left-panel Preset Explorer with search, tags, favorites and recents, undo/redo, tooltips in a bottom bar, and Global Lock ([Neural DSP](https://neuraldsp.com/news/introducing-morgan-amps-suite-x)).

The closest structural match to Plugin Playground is Baby Audio Transit: **seven slots, any effect in any slot, each effect usable once per preset**, four or fewer controls per module, a per-slot strip with bypass, drag handle, preset and dice, and one macro linked through a dot on each control. Sound On Sound called its GUI "something of a triumph" and did not criticize the one-instance limit ([Sound On Sound](https://www.soundonsound.com/reviews/baby-audio-transit)). Kilohearts adds the lowest-friction module picker found: click the empty space at the end of a lane to add a module, with eight macros under the patch name ([Kilohearts docs](https://kilohearts.com/docs/snap_heap)). Larger racks pay for their depth: Guitar Rig 7 needed a new signal-flow sidebar because "things can get pretty busy" ([Sound On Sound](https://www.soundonsound.com/reviews/native-instruments-guitar-rig-pro-7)).

Macro counts cluster by audience: one in Transit, two on Minimal Audio Rift's Play View, four in Minimal Audio Current's Play View, six in NI's Play Series, eight in Kilohearts hosts ([Minimal Audio manual](https://manual.minimal.audio/current-manual/overview-and-navigation/play-view), [NI manual](https://docs.native-instruments.com/online-guides/play-series-manual/en/main-overview)). The cautionary tale is Arturia Analog Lab V, where users revolted when generic macros replaced preset-specific controls such as ADSR, ranges were restricted, and some presets showed "two blank, non-working controls" ([KVR forum](https://www.kvraudio.com/forum/viewtopic.php?p=8296634)). Kilohearts avoids dead knobs in its compact view by showing "only the named macros that have modulation bindings" ([Kilohearts docs](https://kilohearts.com/docs/multipass)).

User-editable front panels exist, but almost always as a fixed number of macro slots that can be reassigned, ranged and sometimes renamed (Current renames by clicking the label; NI's Macro Editor sets min, max, curve and order). The one free-form approach found, Melda's custom easy screens, draws maintenance complaints because adding or removing modules forces rework ([KVR forum](https://www.kvraudio.com/forum/viewtopic.php?p=8113134)).

On locking, **no product found has a play mode that disables editing**. Every "lock" found keeps chosen values when a preset loads or a randomizer runs: Neural's Global Lock holds input, gate, transpose, doubler and output; Minimal Audio locks any control by right-click and shows it in brackets; Output Portal locks Dry/Wet; Transit's locks decide what randomize touches ([Minimal Audio manual](https://manual.minimal.audio/current-manual/additional-settings/parameter-locking), [Output support](https://support.output.com/en/articles/10297849-main-page)). "Play view" in the market means a smaller panel, not a frozen one.

**Recommended.** Keep the existing rule (seven modules, each once, reorderable) and present it as one row of tiles in signal order that serves as both overview and editor, with an empty tile at the end as the add button. "Pick a category, then a type" becomes: click the empty tile, choose a category, choose a type. Hold every module to four dials and one switch on its tile. Keep a persistent strip with the preset name, previous, next, random and favorite, plus input, output and mix, a large value readout, and a hover help bar. Ship undo/redo and drag-to-resize from the start, since competitors had to retrofit both. Answer "where do I start" with a good default preset, a random button and a short curated list per category, and add tags and search only when the preset count demands it.

Offer four macro knobs on the front, renameable, assigned through a visible link dot on each control, full range by default, hidden when unassigned. This is the realistic form of "user-added knobs": the user points a slot at a parameter, and an assignment vanishes cleanly when its module is removed. Do not build a free-form panel editor. For the instrument, show the synth's real controls (oscillator, filter, envelope) directly and treat macros as an addition, which is the lesson of the Analog Lab backlash.

Split the owner's lock idea into two features that the evidence says should not be merged. The first is a play/edit toggle: play shows macros and the tile row with working knobs but no adding, removing or reordering; edit opens everything. This is novel, with Minimal Audio's Play versus Engine views and Kilohearts' pen icon as the nearest precedents. The second is value hold: output, mix and input survive preset changes, on by default. Do not store lock state in presets.

**Thin evidence.** All of this is qualitative, from reviews, manuals and KVR threads; no usability studies or Reddit and Gearspace threads were retrieved. Cory Wong X itself had no hands-on review, so layout praise comes from sibling X plugins. Kilohearts' reorder and remove gestures and Guitar Rig 7's macro count were not confirmed.

## Every shipping modular plugin freezes its host parameter list, and so should this one

**Established.** Three strategies were compared: a fixed superset of all parameters, fixed generic slots whose meaning changes, and a list that really changes at runtime. Only CLAP specifies the third, and it requires a restart, deactivation and `RESCAN_ALL`; the cheap `RESCAN_INFO` path covers only names, modules and the hidden flag, while any change of range or stepped-ness falls in the heavy class ([clap params.h](https://github.com/free-audio/clap/blob/main/include/clap/ext/params.h)). Even Bitwig, the best-supported host, had restart bugs across versions 5.0 to 5.3 ([interop-tracker issue 55](https://github.com/free-audio/interop-tracker/issues/55)). VST3 forbids the idea outright: a plugin "must not perform any reconfigurations that lead to a different set of automatable parameters" ([VST 3 Developer Portal](https://steinbergmedia.github.io/vst3_dev_portal/pages/Technical+Documentation/Parameters+Automation/Index.html)). On Audio Units, **Logic and GarageBand restore automation by parameter order, not ID**, which Apple confirmed as a known limitation unlikely to be fixed; after one plugin update "a pitch lane was read as parameter 8, volume" ([JUCE forum](https://forum.juce.com/t/automated-parameters-are-not-recalled-correctly-in-logic-garageband/61031)).

The wrapper the project depends on closes the question for VST3. Reading clap-wrapper's source at its 2026-11-19 commit shows that `RESCAN_ALL` rebuilds the wrapper's internal list but sends the host only `kMidiCCAssignmentChanged`, never `kReloadComponent`; a text-only rescan is silently dropped; and `RESCAN_INFO` refreshes titles only ([clap-wrapper wrapasvst3.cpp](https://github.com/free-audio/clap-wrapper/blob/main/src/wrapasvst3.cpp)). An open issue describes exactly this product's pattern (a type selector plus fixed hidden slots) freezing a VST3 host when it used the restart path, with a main-thread callback as the workaround ([clap-wrapper issue 418](https://github.com/free-audio/clap-wrapper/issues/418)).

Industry practice agrees. Kilohearts tells users "your DAW cannot keep a complete list of all available parameters" and exposes macros plus 64 assignable slots ([Kilohearts docs](https://kilohearts.com/docs/host_plugins)). Guitar Rig reports 512 fixed IDs, and its remapping function carries the warning that existing automation "will not work correctly any more" ([Guitar Rig manual](https://docs.native-instruments.com/online-guides/guitar-rig-manual/en/automation-and-midi-control)). Surge XT exposes a fixed superset at a fixed 0..1 range with dynamically resolved names so that `RESCAN_ALL` "is never needed" ([surge PR 8600](https://github.com/surge-synthesizer/surge/pull/8600)). No shipping plugin with a truly dynamic count across VST3 and AU was found. The documented failures with fixed lists are cosmetic (stale names in Live after session recall, a ten-second text delay in Reaper); with changing membership or order they become re-pointed or lost automation.

**Recommended.** Use a fixed superset bound to module type, not to chain position. Declare once, for the life of the product: for each of the seven module types, four dials and one switch (35 parameters) plus an enable; one stepped selector per chain position for order; input, output and mix; and eight macro parameters, of which the face shows four by default. Because each module appears at most once, type-bound parameters never change meaning when the user reorders or swaps, so recorded automation stays valid and names never need to change. That removes most of the refresh failures above. The alternative, position-bound slots, keeps the list smaller but silently reinterprets automation on every swap, and it only wins if two instances of one module are ever allowed.

Keep every dial at a fixed 0..1 range with value-to-text conversion in the plugin. Declare each switch as an enum sized for the widest module. Mark the order and enable selectors non-automatable. Never call `request_restart` or `RESCAN_ALL`; send the few live changes (macro renames) as `RESCAN_INFO` paired with `RESCAN_VALUES` from a main-thread callback, batched once per user action, and repeat the announcement shortly after state load because Live ignores it inside `setState` ([Steinberg forum](https://forums.steinberg.net/t/restartcomponent-kparamtitleschanged-during-session-recall/1001494)). Supply the AUv2 order through clap-wrapper's `clap.plugin-auv2-param-ordering/0` extension from the first release, append new modules only at the end, and store a state version number. If a category later gains several types (for example three reverbs), let them share that category's five parameters where the dial meanings match; otherwise append a new block. The instrument plugin gets the synth's parameters followed by the same effect block.

This freeze is the one decision that cannot be revised cheaply after release, so it belongs before any face design is final.

**Thin evidence.** No written source covers how FL Studio or Studio One treat CLAP rescans or hidden flags, how Cubase, Studio One, FL Studio or Reaper treat `kReloadComponent`, or how Logic Smart Controls follow a renamed parameter. The type-bound versus position-bound comparison is reasoned from failure reports; no source compares them directly. Wrapper behaviour comes from reading code and can change between commits.

## WebView2 through CHOC covers Windows; Linux embedding stays a hazard

**Established.** Every framework uses WebView2 on Windows, and it works inside a CLAP `win32` child window if three things are done deliberately. The loader must ship with the plugin (a DLL, a static library, or embedded bytes as CHOC does). The user data folder must be set explicitly, because the default sits next to the host's `.exe` and fails with "Access Denied" in protected directories ([Microsoft: user data folders](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/user-data-folder)). Creation must be asynchronous on the host's UI thread: CHOC once pumped messages to make creation look synchronous, and Live and REAPER crashed when a plugin was inserted and deleted quickly ([choc issue 71](https://github.com/Tracktion/choc/issues/71)). The Evergreen runtime is part of Windows 11 and present on "the vast majority" of Windows 10 machines, with a 2 MB bootstrapper for the rest; the bundled Fixed Version is over 250 MB ([Microsoft: distribution](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)).

CHOC's `choc::ui::WebView` is the only mature piece that drops into a hand-written CLAP plugin without adopting a framework: one ISC-licensed header with the WebView2 loader embedded ([choc_WebView.h](https://github.com/Tracktion/choc/blob/main/choc/gui/choc_WebView.h)). DPF uses it for exactly this on Windows, re-parenting CHOC's window as a child ([DPF WebViewImpl.cpp](https://github.com/DISTRHO/DPF/blob/main/distrho/extra/WebViewImpl.cpp)). The closest precedent to this project's whole architecture is NovoNotes, which ships a web GUI over CLAP with clap-wrapper for VST3 and AU to "over 15,000" users ([NovoNotes slides](https://speakerdeck.com/novonotes/write-0-lines-of-c-plus-plus-building-commercial-audio-plugins-with-rust-and-web-gui)). One developer measured about 100 MB for the shared WebView2 process and about 35 MB per instance ([JUCE forum](https://forum.juce.com/t/webview-vs-juce-graphics/61156)).

The field risks are known. Keyboard handling is unsolved everywhere: a JUCE thread open since October 2024 and still active in September 2026 reports the spacebar and computer-keyboard MIDI not reaching the host while a web view has focus ([JUCE forum](https://forum.juce.com/t/fixing-webview-keyboard-focus-issue/63987)). CHOC has an open nondeterministic load failure tied to its startup message loop ([choc issue 89](https://github.com/Tracktion/choc/issues/89)), names its data folder after the host executable so all CHOC plugins in a DAW share one browser process group, and has no tagged releases. On the wrapper side, an open clap-wrapper issue reports that **Live and REAPER destroy the AUv2 plugin GUI on sample-rate change**, leaving a black window or a crash ([clap-wrapper issue 595](https://github.com/free-audio/clap-wrapper/issues/595)); this affects the macOS window that already ships.

Linux is the weak platform. The only embeddable system web view is WebKitGTK, it embeds only through XEmbed on X11 or XWayland, and CLAP states Wayland embedding "is currently not supported" ([CLAP gui.h](https://github.com/free-audio/clap/blob/main/include/clap/ext/gui.h)). Loading GTK into a host process is a structural hazard, which is why JUCE and DPF run WebKit in a separate child process; CHOC loads it in-process, and one report shows a black window in Bitwig and a locked-up Reaper ([JUCE forum](https://forum.juce.com/t/xembedcomponent-and-choc-webview/60100)). No shipping commercial Linux plugin with a web view was identified. The dependable single-codebase alternative is a GPU-drawn toolkit such as Visage (MIT, v1.0.0, runs in CLAP plugins on all three systems), but none of these reuse the existing HTML and TypeScript face ([VitalAudio/visage](https://github.com/VitalAudio/visage)).

**Recommended.** Keep the macOS WKWebView code. On Windows, add CHOC's header pinned to a commit, re-parent its window under the CLAP parent, return from `create()` and `set_parent()` immediately and finish in the ready callback, and patch the data folder to a vendor folder under `%LOCALAPPDATA%` with fixed options. Have the installer check the runtime registry key and run the bootstrapper if it is missing. Size the window in physical pixels and apply the host's `set_scale` value as the WebView2 rasterization scale. Write an explicit key policy on both systems: the page keeps text input, everything else goes to the host. Make the page stateless: it posts "ready", the plugin answers with a full snapshot, and a main-thread timer sends one batched update at about 30 Hz while visible. That design also survives hosts that destroy and recreate the window. Never call `request_resize` inside `create()`.

Ship Linux without a plugin window for now and rely on the host's generic parameter view, which the type-bound parameter names make usable. If Linux demand appears, the low-risk design is a small helper process that owns GTK and embeds by X11 window ID; that is new code CHOC does not provide. Do not rewrite the face in a native toolkit: it would abandon the project's one shared asset, the web face that also runs on the site.

**Thin evidence.** No source covers WebView2 inside sandboxed or bridged hosts (Bitwig's sandbox, FL Studio bridged mode), startup time, or how clap-wrapper forwards scale on Windows per host. The memory figure is one developer's anecdote. Whether JUCE 9 fixed the keyboard issue was not checked.

## A settings object costs a fraction of a cent, so users' own AI can pay for it

**Established.** Hosted AI plugin makers charge because each request has a large model write and compile DSP code. Free tools push model cost to the user. Reviewers' main complaint about Sonorie is that with no free tier "there is no way to hear how the generated plugins sound before you pay" ([AI Musicpreneur](https://www.aimusicpreneur.com/ai-tools-news/sonorie-ai-audio-plugin-builder-launch/)).

|---|---|---|---|
| Sonorie | Vendor-hosted model | 19.99 USD per month, no free tier | [AI Musicpreneur](https://www.aimusicpreneur.com/ai-tools-news/sonorie-ai-audio-plugin-builder-launch/) (secondary) |
| Studio 56 | Vendor-hosted | 20 free AI requests; Pro 10 USD per month | [bestaipluginmaker.com](https://bestaipluginmaker.com/) (vendor's own site) |

| Amorph | User: copy a prompt into any chatbot, or own key | Free beta, pay what you like | [Synthtopia](https://www.synthtopia.com/content/2026/09/22/free-tool-amorph-builds-custom-plugin-instruments-effects-based-on-your-description/) |
| Audio Plugin Coder | User brings own coding agent | Free, MIT | [Bedroom Producers Blog](https://bedroomproducersblog.com/2026/02/09/noizefield-audio-plugin-coder/) |

Plugin Playground's problem is far smaller: choose options and dial values in a flat, enum-heavy schema. The notes estimate one request at roughly 2,500 input and 800 output tokens, which at published prices is about 0.0005 to 0.0007 USD on the smallest hosted models and 0.01 to 0.05 USD on flagships ([OpenAI pricing](https://developers.openai.com/api/docs/pricing), [Claude pricing](https://platform.claude.com/docs/en/about-claude/pricing), [Gemini pricing](https://aistudio.google.com/docs/pricing)). The token counts are the researcher's estimate, not a measurement. Schema-constrained output makes invalid JSON a non-issue on hosted models, though Anthropic's grammar does not enforce numeric minimum and maximum ([Claude docs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)).

Four ways to get that completion work from a static page, plus one that needs no model:

The no-LLM route has a shipping precedent. Synplant 2's PhenoType turns a typed description into a patch locally with "an algorithmic text parser and a specialized neural network" over hundreds of tags, falls back to a random patch, and was reviewed as limited on abstract prompts yet "creatively inspiring" ([MusicRadar](https://www.musicradar.com/music-tech/is-synplant-2s-new-prompt-based-patch-generator-the-future-of-synthesis)). Forum opinion values randomizers with an amount control whose results are mostly usable.

Copy and paste is Amorph's no-key path: the site builds the prompt, the user pastes it into any chatbot and pastes the answer back. Amorph's pain was looping on compile errors from weak free models ([We Rave You](https://weraveyou.com/2026/03/amorph-review-build-your-own-plugins-with-ai/)).

Chrome's built-in Prompt API reached ordinary pages in Chrome 148 (May 2026) with JSON-schema-constrained output, but needs a desktop with 22 GB free disk and either more than 4 GB of VRAM or 16 GB of RAM, and Mozilla and Apple objected to it ([Chrome for Developers](https://developer.chrome.com/docs/ai/prompt-api)). A September 2026 preprint found constrained decoding gives 100 percent schema validity on small models, while warning it fixes structure, not meaning ([arXiv 2609.23742](https://arxiv.org/html/2609.23742v1)).

OpenRouter's PKCE flow is the one "sign in with your AI account" option that works from a static site with no app registration: one redirect returns a user-owned key, and the site can prefill a credit limit and expiry ([OpenRouter OAuth docs](https://openrouter.ai/docs/guides/overview/auth/oauth.md)). Its free models allow 50 requests a day for accounts with fewer than 10 credits purchased ([OpenRouter limits](https://openrouter.ai/docs/api/reference/limits)).

A pasted key works from the browser for Anthropic, with the header `anthropic-dangerous-direct-browser-access: true` ([Simon Willison](https://simonwillison.net/2024/Aug/23/anthropic-dangerous-direct-browser-access)), and reportedly for Gemini; sources conflict on OpenAI. A key in `localStorage` is readable by any script on the page.

A project-held free-tier key behind a serverless proxy is free at hobby scale (Cloudflare Workers AI gives 10,000 neurons a day) but needs a server, a secret, abuse controls and monitoring ([Cloudflare pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/)). GitHub Models was retired on 30 July 2026 ([GitHub Docs](https://docs.github.com/en/github-models/use-github-models/prototyping-with-ai-models)).

**Recommended.** Build a ladder on the website, cheapest and most universal first. Step one, no model: a hand-written table mapping sound words to dial moves, "variations" that jitter dials around the current device by a user-set amount, and "breed" that interpolates two liked results. Every result is valid by construction, it works offline, and it is the fallback under every other step. Step two, "Copy AI prompt": the site assembles schema, module descriptions, a few worked examples and the user's sentence; the pasted reply is validated and every dial clamped. A small JSON object avoids Amorph's error loop because the site repairs or rejects values deterministically. Step three, progressive enhancement: use Chrome's built-in model when `LanguageModel.availability()` says it is there. Step four, "Sign in with OpenRouter" with a prefilled 1 USD limit and short expiry, and an optional key field for Anthropic and Gemini kept in memory for the tab by default.

Keep all model calls on the site, and keep the plugin fully offline; a plugin that needs the network draws user complaints ([KVR thread](https://www.kvraudio.com/forum/viewtopic.php?p=9026626)). Defer the WebLLM route (a 0.7 to 2 GB download is a heavy ask) and the proxy, which contradicts the no-server preference and whose provider terms for anonymous public use were not checked. Position the product on what hosted rivals cannot match: free, no account, and the result plays in the browser before any install.

**Thin evidence.** No public BYOK conversion or drop-off data exists. No benchmark measures small models on synth or effect parameters, so musical quality of results is untested. The OpenRouter combination of an OAuth-issued key, zero credits and a free model was not tested. Edge's Prompt API status is contradictory. Sonorie and Pluginmaker.ai prices rest on secondary or competitor-run sources.

## Trust costs 99 USD a year on macOS and has no instant fix on Windows

**Established.** One Apple Developer Program membership at **99 USD per year**, open to individuals, supplies both needed certificates: Developer ID Application for the app and plugin bundles and Developer ID Installer for the `.pkg` ([Apple](https://developer.apple.com/programs/whats-included/)). Notarization requires Developer ID signatures, hardened runtime and a secure timestamp, and one `notarytool` submission of the `.pkg` produces tickets for everything nested inside, usually within five minutes ([Apple: notarization workflow](https://developer.apple.com/documentation/security/customizing-the-notarization-workflow)). Since macOS 15, Control-click no longer overrides Gatekeeper; users of an un-notarized download must go to System Settings, Privacy & Security, Open Anyway ([Apple Developer News](https://developer.apple.com/news/?id=saqachfa)). On macOS 26 all code must carry at least a valid ad hoc signature, and a quarantined ad hoc app is offered Move to Trash at launch ([Eclectic Light Company](https://eclecticlight.co/2026/08/11/how-can-you-run-code-that-hasnt-been-notarised/)). Open source peers (Surge XT, plugdata) sign under a maintainer's individual Developer ID in GitHub Actions and skip signing when the secret is absent.

On Windows, "EV certificates no longer bypass SmartScreen", and reputation "can take several weeks and hundreds of clean installs"; unsigned files restart from zero with every new build, and Smart App Control on Windows 11 blocks unsigned executables of any kind, not only downloads ([Microsoft Learn: SmartScreen](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation)).

|---|---|---|---|---|
| Azure Artifact Signing | about 9.99 USD per month | Individuals in the USA and Canada only | Initial warnings still expected | [Microsoft Learn](https://learn.microsoft.com/en-us/azure/artifact-signing/quickstart) |
| OV certificate | 150 to 300 USD per year | Worldwide | Key on hardware token or cloud HSM | [Microsoft Learn](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options) |

| EV certificate | 400 USD or more per year | Worldwide | "Same as OV since 2024" | [Microsoft Learn](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options) |

Windows plugins belong in `Common Files\VST3` and `Common Files\CLAP`, which need administrator rights; per-user folders exist in both specifications, but one user's survey found Live and FL Studio do not scan the per-user VST3 folder ([Image-Line forum](https://forum.image-line.com/viewtopic.php?p=2075782)). Inno Setup is the common installer among small makers. Users praise installers that are fast, single-screen and explicit about formats, and complain about manager apps that stall or hide what they install ([KVR thread](https://www.kvraudio.com/forum/viewtopic.php?p=9182272)).

One finding bears directly on the product shape. A plugin bundle generated on the user's Mac is re-signed ad hoc, so it has no Team ID and no notarization ticket; it loads for its maker because it carries no quarantine flag, but sent to another Mac it arrives as "unidentified developer". Blue Cat's Plug'n Script users hit exactly this, and the vendor's answer was that "there is no known way around" Apple's check ([KVR thread](https://www.kvraudio.com/forum/viewtopic.php?p=8461654)).

**Recommended.** The unified plugin removes that problem, and this is the strongest argument for it. Two byte-identical plugins signed with Developer ID and notarized once never need re-signing, never need new Audio Unit subtypes or VST3 class IDs per device, and work on any Mac. Devices become data files that users share freely, which also keeps the maker's manufacturer name off binaries nobody reviewed. On Windows the same holds: a signed DLL plus a separate device file keeps its signature.

Pay for the Apple membership before the Download tab launches, sign in CI with an App Store Connect API key, and notarize and staple the `.pkg`. Treat Windows signing as second priority: ship the Inno Setup installer unsigned at first with a stable release file (not per-commit builds), show the exact "More info, Run anyway" clicks on the download page, then sign both installer and plugin binaries through whichever route the owner's country and license allow. Never buy EV. Install system-wide by default. Give the installer one screen with format checkboxes and a real uninstall. Avoid "VST" in product names and add Steinberg's attribution line where VST3 is mentioned ([Steinberg usage guidelines](https://steinbergmedia.github.io/vst3_dev_portal/pages/VST+3+Licensing/Usage+guidelines.html)). Yearly cost by the notes' arithmetic: 99 USD for macOS alone, about 170 USD in the first year with Certum, about 219 USD with Azure where eligible.

**Thin evidence.** No Apple document states that an ad hoc signed, unquarantined Audio Unit loads in Logic on Apple silicon; the support is the entitlements observed on Apple's hosting services and `auval` passing. Entitlements of Live, Bitwig, REAPER, Cubase, FL Studio and Studio One on macOS were not checked. No data quantifies abandonment at Gatekeeper or SmartScreen prompts. Developer ID certificate validity, Certum renewal pricing and SignPath's likely verdict on this project are unconfirmed. Whether Azure-signed files earn SmartScreen trust faster is disputed between practitioners and Microsoft.

## The recommended order: prove hosts first, ship macOS second, widen third

Everything in this section is recommendation. It orders the work so that irreversible decisions come after cheap tests and each phase ships something usable.

| Phase | Build | Why now |
|---|---|---|
| 0. Risk tests (days, no product work) | Load today's CLAP, VST3 and AU builds in Logic, Live, REAPER, Bitwig, FL Studio and one of Cubase or Studio One. Build a throwaway plugin with the proposed frozen list and check automation recall, macro rename and state restore in each. Change sample rate with the AU window open in Live and REAPER. Spike WebView2 through CHOC on Windows. Confirm Apple enrollment and which Windows signing routes the owner qualifies for. | The README says no generated plugin has been loaded in a DAW. The parameter list cannot change after release. |
| 1. Unified effect plugin, macOS | Frozen type-bound parameter list with AUv2 ordering. Devices as data files. Face: tile row, add tile, global strip with previous, next, random, value hold on output and mix, undo/redo, resize. Notarized `.pkg`. Download tab with the installer, a small curated preset set per category that plays in the browser, and a way to open a device file in the plugin. | Delivers goals (a) and most of (b) on the platform where the window already works, and retires the re-signing risk. |
| 2. Widen | Windows window and Inno Setup installer, signed when a route is settled. Unified instrument plugin on the same pattern. Four assignable, renameable macros with link dots. Play/edit toggle. Tags, favorites and search once presets outgrow a short list. | Each item builds on the frozen list and the stateless page from phase 1. |
| 3. Assist | On the site: keyword table, variations with an amount control, breed. Then "Copy AI prompt". Then Chrome's built-in model, then OpenRouter sign-in and an optional key field. | Delivers goal (c) at zero project cost; the no-model steps come first because they reach every visitor. |

Defer: a Linux plugin window (generic host view until demand justifies a helper process), in-browser model downloads through WebLLM, a serverless proxy with a project-held key, AAX and AUv3, and any marketplace (the one launched competitor marketplace was empty and none publishes a commission). Drop: runtime changes to the parameter count, position-bound slots, a free-form panel editor, a fully frozen "locked" panel, the WebView2 Fixed Version runtime, EV certificates, and a native-toolkit rewrite of the face. Keep per-device named plugins as an existing export for people who want them, but stop investing in them and do not present them as shareable.

The open risks to test early, in order of how much they could change the plan: whether wrapped plugins load and recall state correctly across the major hosts at all, including the known Live issue where default values overwrite loaded state in a wrapped VST3 ([clap-wrapper issue 303](https://github.com/free-audio/clap-wrapper/issues/303)); whether the AU window survives sample-rate changes in Live and REAPER; whether Logic keeps automation intact with the explicit order extension; how FL Studio and Studio One treat renamed CLAP parameters; whether the Windows web view survives quick insert and delete, two instances, two DAWs at once, the spacebar, and 150 percent scaling; whether a small or free model maps words like "warm tape wobble" to sensible dials given a good prompt; and whether OpenAI accepts browser calls. One product question the research did not address is how a device chosen on the site reaches the installed plugin (a downloaded file, a watched folder, or a pasted code); it needs a design decision in phase 1.

## Conclusion

The five research strands converge on one architectural move that none of them set out to find: once a device is data and the plugin is fixed, the hard problems shrink together. The parameter list stops changing, so automation is safe in Logic and through the wrapper. The binaries stop changing, so one notarization covers every user and sharing a sound means sharing a file. The AI problem shrinks from generating code to filling a small validated object, which is cheap enough that the project never needs to pay for it or run a server. The owner's three goals are therefore one product, not three.

The trade is flexibility for permanence. A frozen list and a once-per-module chain rule out duplicate modules and make every future module an append-only commitment, and the web face ties the project to web view behaviour it does not control on Windows and to two open wrapper defects on macOS. Those are acceptable costs only if phase 0 confirms the foundation, which is why a few days in real DAWs, before any new feature, is the most valuable work available.
