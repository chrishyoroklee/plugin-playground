# AI-assisted sound design without the project paying for inference (researched 2026-11-21)

Reading notes for the report writer:

- All prices and limits were read on 2026-11-21 unless a different date is given. They change often. Each has its URL.
- Several web pages were read through an automated fetch that summarises the page. Where a figure matters, check the linked page before publishing it.
- "Static-only" below means it works from GitHub Pages with no server, no accounts run by the project and no payment processing run by the project. Anything that breaks that is marked NEEDS SERVER.
- Working assumption used for every cost estimate (my own estimate, not a sourced figure): one "describe the sound" request is about 2,500 input tokens (a system prompt explaining the 7 modules and dial ranges, about 1,000; a 2 KB JSON schema, about 700; the current device JSON for an edit, about 700; the user's sentence, about 100) and about 800 output tokens (a 1 to 3 KB device JSON). Models with always-on thinking add output tokens on top, so real cost can be 1.5 to 3 times the figure shown unless effort is set low.

## 1. Bring-your-own-key (BYOK) in a browser-only app

### Takeaway
BYOK is technically workable from a static page for Anthropic (with an explicit opt-in header) and Gemini, and reportedly for OpenAI although sources conflict; the price is a narrow audience, because only people who already hold a paid API account and understand keys will complete the setup. No published conversion or drop-off numbers were found.

### Cited Findings
- Anthropic's API accepts direct browser (CORS) calls only when the request carries the header `anthropic-dangerous-direct-browser-access: true`, sent alongside the usual `x-api-key` and `anthropic-version` headers. Added August 2024. Without it, developers report a 401 `authentication_error` saying CORS requests must include the header. [Simon Willison, 2024-08-23](https://simonwillison.net/2024/Aug/23/anthropic-dangerous-direct-browser-access); [DEV write-up of a 150-line BYOK tool](https://dev.to/sendotltd/calling-the-anthropic-api-directly-from-the-browser-a-150-line-byok-comparison-tool-for-opus--nh)
- The official OpenAI and Anthropic JavaScript SDKs refuse to run in a browser unless constructed with `dangerouslyAllowBrowser: true`. [OpenAI SDK ClientOptions reference](https://jsr.io/@openai/openai@6.49.0/doc/~/ClientOptions.dangerouslyAllowBrowser)
- Simon Willison reported in September 2024 that OpenAI and Google Gemini also accept direct browser calls, without needing a special header. [Simon Willison weeknotes, 2024-09-06](https://simonwillison.net/2024/Sep/6/weeknotes/). CONFLICT: later developer posts say OpenAI does not return `Access-Control-Allow-Origin` for browser origins "by design", and OpenAI community threads report browser requests that had worked starting to fail with CORS errors. [DEV: "That OpenAI call from your browser is failing"](https://dev.to/tracepilot_2841f1db6718a1/that-openai-call-from-your-browser-is-failing-heres-why-3p3c); [OpenAI community: "Has the CORS policy changed (responses API)?"](https://community.openai.com/t/has-the-cors-policy-changed-responses-api/1372791); [OpenAI community: endpoint blocked for browser requests](https://community.openai.com/t/chat-completions-api-endpoint-down-blocked-any-web-browser-request/1362527). Treat OpenAI browser access as unconfirmed and test it before promising it.
- Gemini's OpenAI-compatible endpoint has thrown CORS errors when called with the OpenAI JS library from a browser; the reported workaround was removing the SDK's `x-stainless-*` headers. Anecdotal forum report. [Google AI developer forum](https://discuss.ai.google.dev/t/gemini-api-cors-error-with-openai-compatability/58619)
- The pattern "prompt for the user's own key, store it in `localStorage`, call the provider directly" is exactly how Simon Willison runs his free tools on GitHub Pages with no server code. He names the drawback himself: it limits use to people who understand API keys and already have an account with a major provider. [Simon Willison weeknotes, 2024-09-06](https://simonwillison.net/2024/Sep/6/weeknotes/)
- Security of a key in `localStorage`: it is stored unencrypted, so any cross-site-scripting bug (including a compromised third-party script) can read and exfiltrate it; recommended mitigations are hardening against XSS, using keys with small spending limits, telling users plainly how the key is handled and advising them to revoke keys they no longer need. [marussy.com, 2024-12-23](https://marussy.com/pkce-authentication/)
- A desktop-app developer lists the steps BYOK forces on a user before anything works: create a provider account, generate a key, paste it, confirm the model is available, and make sure the account has credit. [DEV: "BYOK: why I let users bring their own LLM key"](https://dev.to/baur_442c4cd/byok-why-i-let-users-bring-their-own-llm-key-instead-of-running-my-own-api-18l3)
- In the same product category, BYOK is already the norm for the free tools: Noizefield Audio Plugin Coder (free, MIT) has the user bring their own AI coding agent; Amorph (free beta) lets the user paste a generated prompt into any chatbot with no key at all, or use an assistant with the user's own key; ChatDSP ($10 or more) uses the user's own Anthropic or OpenAI credits, a local model, or manual copy and paste. [bestaipluginmaker.com](https://bestaipluginmaker.com/) (this site is published by a competitor, Studio 56, and says its entries are taken from each maker's page, not tested)
- Amorph's no-key path in practice: describe the idea, click "Copy AI Prompt", paste into a chatbot, paste the answer back, click Compile; on an error, paste the error back to the chatbot. The reviewer found the free Gemini tier looped on errors and a paid tier still needed "a lot of back-and-forth". [We Rave You review, March 2026](https://weraveyou.com/2026/03/amorph-review-build-your-own-plugins-with-ai/)

### Inferences
- The copy-and-paste path (Amorph's "Copy AI Prompt") fits Plugin Playground unusually well. The site can put the schema, the module list and the user's sentence into one prompt, the user pastes it into whatever chatbot they already use (free ChatGPT, Claude, Gemini), and pastes back a 1 to 3 KB JSON object that the site validates. It costs nobody an API key, needs no CORS and no storage of secrets. Amorph's pain came from round-tripping compile errors on generated code; a small validated JSON object should not have that loop, because the site can repair or reject values deterministically.
- If a key field is offered, Anthropic and Gemini are the two providers where browser access looks dependable; OpenAI needs a live test.
- Because the site has no server, the key never leaves the user's browser except to the provider. That is a real and explainable privacy point, but the page must have no third-party scripts that could read `localStorage`. Offering "keep for this tab only" (memory or `sessionStorage`) as the default and "remember on this device" as an opt-in reduces exposure.
- Pyodide is not needed for any of this; a plain `fetch` from JavaScript is simpler. (Simon Willison has run an OpenAI plugin for his LLM tool inside Pyodide, so it is possible: [link](https://simonwillison.net/2025/Nov/9/llm-pyodide-openai-plugin/), title only, not read.)

### Gaps
- No published funnel data, A/B test or postmortem with BYOK conversion or drop-off numbers was found in two searches. Every source describes the friction qualitatively. Report this as "unmeasured in public sources", not as a known percentage.
- Anthropic's own documentation page for the browser header was not located; the header is confirmed from secondary sources and from many open-source projects that use it.
- Whether Gemini API keys can be restricted by HTTP referrer for the Generative Language API in 2026 was not confirmed.

## 2. "Sign in with your own AI account" options that avoid pasting keys

### Takeaway
OpenRouter's PKCE flow is the one option that is fully static-site compatible, needs no app registration and bills the user; Puter.js is the lowest-friction "user pays" option but ties the feature to a Puter account and an unstated allowance; Hugging Face OAuth works but free Hugging Face accounts now get no included inference credit.

### Cited Findings
- OpenRouter PKCE flow: (1) generate a random `code_verifier` and its SHA-256 `code_challenge`; (2) send the user to `https://openrouter.ai/auth?callback_url=<site>&code_challenge=<challenge>&code_challenge_method=S256`; (3) OpenRouter redirects back with `?code=`; (4) POST `code`, `code_verifier` and `code_challenge_method` to `https://openrouter.ai/api/v1/auth/keys`, which returns a user-controlled API `key`; (5) use it as a Bearer token. Optional parameters prefill a key label, a credit `limit` in USD and an `expiration` (1 hour up to never). By default the key has no credit limit and no expiry. No separate app registration step is described. Hosted apps must use an `https://` callback. Usage is billed to the user's OpenRouter credits. [OpenRouter OAuth docs](https://openrouter.ai/docs/guides/overview/auth/oauth.md)
- The same OpenRouter page, as summarised by the fetch tool, advises storing keys encrypted server-side or in an OS keychain and not in browser storage. A static site cannot follow that advice, so the mitigations in the next bullet matter. [OpenRouter OAuth docs](https://openrouter.ai/docs/guides/overview/auth/oauth.md)
- Risk analysis of the client-only variant: PKCE here hands back a long-lived key that can spend the user's money, so it is more sensitive than a normal single-page-app login. Mitigations: request a small spending limit, remove the `code` from the URL and history after exchange, delete the verifier from `sessionStorage`, harden against XSS, and tell users how to revoke. [marussy.com, 2024-12-23](https://marussy.com/pkce-authentication/)
- OpenRouter free models (IDs ending `:free`): 20 requests per minute; 50 requests per day for accounts that have bought fewer than 10 credits in total, 1,000 per day once at least 10 credits have been bought. [OpenRouter limits reference](https://openrouter.ai/docs/api/reference/limits)
- Puter.js "User-Pays" model: each user signs in with their own Puter account and pays for what they consume; "Every user starts with a free monthly allowance"; when it runs out Puter prompts the user to upgrade; the developer pays nothing for users' usage and needs no API key. The page does not state the size of the allowance. [Puter docs: User-Pays Model](https://docs.puter.com/user-pays-model/); [Puter pricing](https://developer.puter.com/pricing/)
- Puter's own tutorials market this as "free, unlimited" access to many models; that wording is Puter's marketing and is not reconciled in the docs with the per-user allowance. [Puter tutorial example](https://developer.puter.com/tutorials/free-llm-api/)
- Hugging Face OAuth has an `inference-api` scope: "Get access to the Inference Providers, you will be able to make inference requests on behalf of the user." There is an official client-side example for static Spaces using huggingface.js. [HF Hub OAuth docs](https://huggingface.co/docs/hub/en/oauth); [HF Spaces OAuth docs](https://huggingface.co/docs/hub/spaces-oauth)
- Hugging Face Inference Providers billing as of the page read 2026-11-21: free users get no monthly credits and must buy credits; PRO users get $2.00 per month; pay-as-you-go beyond that at provider rates with no Hugging Face markup. [HF Inference Providers pricing](https://huggingface.co/docs/inference-providers/pricing)

### Inferences
- OpenRouter is the strongest fit: one button, no key pasting, no registration, works from GitHub Pages, and the site can prefill a small credit limit (for example $1) and a short expiry so a leaked key is nearly harmless. A user with a new OpenRouter account and no credits should still be able to call `:free` models at 50 requests a day, which would make the feature free to both sides, but this combination (OAuth-issued key plus zero-credit account plus free model) was not tested and free models can change or vanish.
- At roughly $0.0005 to $0.002 per request on small paid models (section 4), a $5 OpenRouter top-up covers thousands of requests, so "user pays" is not a meaningful cost to the user; the barrier is the sign-up step, not the money.
- Puter is the least effort to code (one script tag, no key) but it puts a third-party sign-in popup and an allowance of unknown size between the user and the feature, and the project would depend on Puter's business model continuing.
- Hugging Face OAuth is now a weak option for casual users because a free account has no credit; it mainly helps users who already pay Hugging Face. Whether OAuth works for a site hosted outside Hugging Face Spaces requires registering an OAuth app, which was not checked in detail.

### Gaps
- Puter's free monthly allowance amount and its rate limits were not found on the pages read.
- The OpenRouter platform fee on credit purchases is not stated on the pages read.
- No other 2025 to 2026 "sign in with your AI account" service for static sites was confirmed. In particular no evidence was found that Anthropic, OpenAI or Google offer third-party browser apps an OAuth sign-in that spends a consumer subscription.

## 3. In-browser local models

### Takeaway
Chrome's built-in Prompt API (Gemini Nano) reached ordinary web pages in Chrome 148 (May 2026) and supports JSON-schema-constrained output with zero download managed by the site, but only on well-equipped desktops and only in Chrome (and possibly Edge); WebLLM or Transformers.js on WebGPU reach more browsers at the cost of a 0.7 to 2 GB model download. With constrained decoding, 3 to 4 billion parameter models produce schema-valid JSON every time and near-perfect content on benchmark tasks, so the remaining risk is musical judgment, not format.

### Cited Findings
- Chrome Prompt API availability: listed for web pages from Chrome 148 and for extensions from Chrome 138. Page last updated 2026-10-21. [Chrome for Developers: Prompt API](https://developer.chrome.com/docs/ai/prompt-api). Chrome 148 shipped it to web pages on 2026-05-05, using Gemini Nano, downloaded on first use. [WebML article](https://www.webml.ai/articles/prompt-api-web-pages-chrome-148)
- Chrome Prompt API requirements: Windows 10 or 11, macOS 13 or later, Linux, or ChromeOS on Chromebook Plus; at least 22 GB free on the profile volume (model removed if free space later falls below 10 GB); a GPU with more than 4 GB VRAM, or a CPU path with 16 GB RAM and 4 or more cores; an unmetered connection for the first download. Chrome on Android and iOS is not supported. Input languages: en, ja, es, de, fr. [Chrome for Developers: Prompt API](https://developer.chrome.com/docs/ai/prompt-api)
- Structured output in the Prompt API: pass a JSON Schema as `responseConstraint` to `prompt()` or `promptStreaming()`; available since Chrome 137. The schema counts against the context window. [Chrome for Developers: structured output](https://developer.chrome.com/docs/ai/structured-output-for-prompt-api)
- Standards position: Mozilla, Apple (WebKit), and others formally objected before the Chrome 148 release; Firefox and Safari have no equivalent embedded model and none is on a near-term timeline. Recommended practice is to build the fallback first, treat the API as progressive enhancement, and call `LanguageModel.availability()` before creating a session. [WebML article](https://www.webml.ai/articles/prompt-api-web-pages-chrome-148); [The Register, 2026-04-30](https://www.theregister.com/software/2026/04/30/mozilla-pushes-back-against-googles-prompt-api/5223409)
- Edge: a February 2026 report compared Chrome's Gemini Nano with Edge's Phi-4-mini-instruct behind the same API and found Edge failed more often (17 percent against 6 percent). CONFLICT: one developer post says Edge disabled the feature, while Chrome's documentation lists Edge on Windows and macOS as supported. [The Register, 2026-04-30](https://www.theregister.com/software/2026/04/30/mozilla-pushes-back-against-googles-prompt-api/5223409); [DEV: "The Quiet AI War Inside Your Browser"](https://dev.to/obetomuniz/the-quiet-ai-war-inside-your-browser-22hd) (search-result summaries; not read in full)
- WebGPU support (needed by WebLLM and by Transformers.js GPU mode): on by default in Chrome and Edge 113 and later, Chrome for Android, and Safari on iOS 26 and later; "partial" in Safari on macOS 26 and 27; disabled by default in Firefox. 86.83 percent of global usage fully supported, 88.63 percent including partial. [caniuse.com/webgpu](https://caniuse.com/webgpu), read 2026-11-21
- WebLLM (MLC): runs LLMs in the browser on WebGPU with an OpenAI-style API; supports JSON mode and custom JSON schemas, implemented in the WebAssembly part of the model library; weights are cached via the Cache API by default, with IndexedDB and OPFS as options. Prebuilt small models include Qwen 0.5B and 1.5B, Phi 3 family, Gemma 2B and Llama 3.2 1B. [github.com/mlc-ai/web-llm](https://github.com/mlc-ai/web-llm)
- Approximate download sizes from third-party catalogues (not official): Llama 3.2 1B at 4-bit about 700 to 750 MB; Qwen2.5 1.5B at 4-bit about 1,100 MB; a 3B model about 1,900 MB; a 7B model about 4 GB. WebLLM's per-model `vram_required_MB` values are hand-set estimates in its config. [jvoltci WebGPU and WebLLM notes](https://jvoltci.github.io/mosaic/edge-ai/browser/webgpu-webllm); [WebLLM pull request discussion](https://create.preset.workers.dev/mlc-ai/web-llm/pull/490) (search-result summaries)
- Small-model structured-output quality, September 2026 preprint, 14 tasks. Schema validity without constrained decoding: Llama 3.2 1B 78.6 percent, Llama 3.2 3B 78.6, Qwen3 0.6B 92.9, Phi-4-mini (3.8B) 92.9, Qwen3 4B 100. With constrained decoding (Outlines or XGrammar): 100 percent for all five. Content accuracy under XGrammar: Llama 1B 0.986, Llama 3B 0.991, Qwen3 0.6B 0.943, Phi-4-mini 1.000, Qwen3 4B 1.000. The paper recommends XGrammar with a 3 to 4B model as the cheapest reliable setup and warns that constrained decoding fixes structure, not meaning: "CD's reach ends exactly where schema conformance ends." XGrammar overhead: 4 to 8 ms schema compile and 1.6 to 3.7 percent throughput loss. [arXiv 2609.23742](https://arxiv.org/html/2609.23742v1)
- JSONSchemaBench (about 10,000 real-world schemas) found that complex real schemas remain hard for both models and constrained-decoding frameworks. [arXiv 2501.10868](https://arxiv.org/html/2501.10868v3)
- Transformers.js on WebGPU also runs in the browser; for a small embedding model (all-MiniLM-L6-v2, 22M parameters) one benchmark run showed about 32 ms per item on WebGPU against about 378 ms on WASM. [HF WebGPU embedding benchmark Space](https://huggingface.co/spaces/Xenova/webgpu-embedding-benchmark/discussions/3)

### Inferences
- A sensible ladder for a static site: (a) if `LanguageModel.availability()` reports the Chrome model is ready or downloadable, use it with `responseConstraint`: no key, no cost, no download hosted by the project; (b) otherwise offer an opt-in WebLLM download of a 1.5 to 4B model with a clear size warning; (c) otherwise fall back to copy-and-paste, OpenRouter sign-in or the non-LLM search in section 6.
- Plugin Playground's schema is small, flat and enum-heavy (7 module types, short option lists, 2 to 4 numbers each), which is the easy end of the constrained-decoding problem. Structure will be right; whether "warm tape wobble" maps to sensible dial values is the open question and depends on the prompt containing a plain description of what each dial does plus a few worked examples.
- Numeric ranges cannot be relied on from the grammar alone in every engine, so the site should clamp every dial to its known range after parsing. That check is cheap because the site already knows the ranges.
- The 22 GB free-disk and 4 GB VRAM or 16 GB RAM rules, plus desktop-only, mean the built-in model will be absent for many visitors, especially on phones and older laptops. No sourced estimate of the eligible share exists.
- A 0.7 to 2 GB download for a "describe a sound" box is a heavy ask on a free toy-like site; it should never start without an explicit click.

### Gaps
- No primary source gives the share of Chrome users whose devices qualify for Gemini Nano.
- Edge's current (November 2026) Prompt API status is contradictory in the sources and was not resolved.
- No benchmark was found that measures small models on audio or synth parameter generation specifically; the quality figures are for generic extraction and function-call tasks.
- Official WebLLM VRAM and size figures per model were not retrieved; the sizes above are third-party approximations.
- Firefox's own on-device AI APIs for web pages (if any) were not confirmed.

## 4. Structured output reliability and per-request cost on hosted models

### Takeaway
All three major providers offer schema-constrained decoding that makes syntactically invalid or schema-violating JSON a non-issue on completed responses; a request of this size costs roughly $0.0005 on the cheapest small models and $0.01 to $0.05 on flagship models, so 1,000 requests cost between about 50 cents and about $50 depending on model.

### Cited Findings
- Anthropic structured outputs: stable (not beta) on the Claude API; constrained decoding gives "always valid" JSON with guaranteed field types and required fields, "no retries needed for schema violations". Schema goes in `output_config.format` with `type: "json_schema"`. Supported on current Haiku, Sonnet, Opus and Fable models. Not supported in schemas: numeric `minimum`, `maximum`, `multipleOf`; string length limits; recursive schemas; `additionalProperties` other than `false`. Supported: `enum` and `const` of simple values, `anyOf`, `$ref`. First request with a new schema is slower while the grammar compiles; compiled grammars are cached 24 hours. An extra system prompt describing the format is added and billed as input. [Claude docs: structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)
- OpenAI structured outputs: constrains completed, non-refusal output to the supplied JSON Schema; the application must still handle refusals (a `refusal` field), incomplete responses (for example `max_output_tokens`) and business rules the schema cannot express; first request with a new schema is slower. [OpenAI docs: structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs)
- Gemini and OpenAI are both among the six constrained-decoding engines evaluated in JSONSchemaBench, which confirms Gemini offers schema-constrained output. [arXiv 2501.10868](https://arxiv.org/html/2501.10868v3)
- Anthropic prices per million tokens (input / output), from the Claude API reference bundled with this research tool, cached 2026-11-03; verify at [Claude pricing](https://platform.claude.com/docs/en/about-claude/pricing): Claude Haiku 5.5 $0.10 / $0.50 (prompts up to 100K tokens); Claude Sonnet 5.5 $2 / $10; Claude Opus 5.5 $4 / $20; Claude Fable 5.2 $8 / $40; older Claude Haiku 4.5 $1 / $5.
- OpenAI prices per million tokens, standard tier, page read 2026-11-21 (page notes some promotional pricing running to 2026-11-30): gpt-5-nano $0.05 / $0.40; GPT-6 Luna $0.10 / $0.50; gpt-5.4-nano $0.20 / $1.25; gpt-5-mini $0.25 / $2.00; gpt-6.1-terra $1 / $5; gpt-6.2-sol $2 / $10; gpt-6.2-astra $8 / $40. [OpenAI API pricing](https://developers.openai.com/api/docs/pricing)
- Google Gemini prices per million tokens, standard tier, page read 2026-11-21: Gemini 2.5 Flash-Lite $0.10 / $0.40; Gemini 3.1 Flash-Lite $0.25 / $1.50; Gemini 3.5 Flash-Lite $0.30 / $2.50; Gemini 3.8 Flash $0.75 / $3.75 until 2026-12-31, then $1.50 / $7.50; Gemini 4 Carbon $2 / $10 until 2026-12-01, then $4 / $20; Gemini 4 Neon $3 / $15. [Gemini API pricing](https://aistudio.google.com/docs/pricing) (redirected from ai.google.dev/gemini-api/docs/pricing; the fetch read the first 100,000 characters only)

### Inferences
Worked estimates for one request at the stated assumption (2,500 input tokens, 800 output tokens, no thinking overhead, no caching). Formula: input x price / 1,000,000 + output x price / 1,000,000.

- The task (pick options and dial values in a small fixed schema) is well inside what the smallest hosted models do; flagship models are not needed. At small-model prices a user's own $5 of credit covers on the order of 5,000 to 10,000 requests.
- Even if the project did pay, 10,000 requests a month on a small model is about $5 to $7. The real exposure is not normal use but abuse of an open endpoint (section 5).

- "Edit this device" requests can send the current JSON and ask for the full object back; at 1 to 3 KB there is no need for a patch format.

### Gaps
- The token counts are estimates. Real counts depend on the tokenizer (newer Claude tokenizers can use up to about 1.35 times as many tokens as older ones) and on the final schema; measure with each provider's token counter before quoting.
- Gemini's response-schema documentation was not read directly; its supported schema subset and limits are not recorded here.
- No independent 2026 measurement of content accuracy (as opposed to format validity) for hosted small models on this kind of task was found.

## 5. Free tiers and low-cost hosting instead of user-paid inference

### Takeaway
A project-held free-tier key behind a small serverless proxy can be free to run at hobby scale (Gemini free tier, Cloudflare Workers AI 10,000 neurons a day, OpenRouter free models), but it NEEDS A SERVER, turns the project into the party that gets rate-limited or abused, and on Gemini's free tier sends user prompts to Google for product improvement. GitHub Models is gone.

### Cited Findings
- Gemini API free tier, page read 2026-11-21: free of charge for Gemini 4 Hydrogen, 3.8 Flash, 3.6 Flash, 3.5 Flash-Lite, 3.1 Flash-Lite, 3 Flash Preview and 2.5 Flash-Lite; not available for Gemini 4 Carbon, Argon, Neon or 3.1 Pro Preview. Free-tier content is used to improve Google's products; paid-tier content is not. [Gemini API pricing](https://aistudio.google.com/docs/pricing)
- Gemini free-tier rate limits are no longer published as a fixed table; the docs say limits depend on usage tier and are shown per project in Google AI Studio. Limits apply per project, not per key, and daily quotas reset at midnight Pacific. Older third-party figures (for example 15 requests per minute and 1,500 per day for 2.5 Flash, or 10 per minute and 500 per day) are stale snapshots. [Gemini rate limits docs](https://ai.google.dev/gemini-api/docs/rate-limits); [apidog 2026 guide](https://apidog.com/blog/gemini-api-free-tier/) (search-result summaries)
- Cloudflare Workers AI: 10,000 neurons per day free, reset at 00:00 UTC; beyond that requires the Workers Paid plan at $0.011 per 1,000 neurons. Example model prices per million tokens (input / output): llama-3.2-1b-instruct $0.027 / $0.201; llama-3.2-3b-instruct $0.051 / $0.335; llama-3.1-8b-instruct-fp8-fast $0.045 / $0.384; gemma-3-12b-it $0.345 / $0.556; granite-4.0-h-micro $0.017 / $0.112. [Cloudflare Workers AI pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/)
- Groq: base limits listed for openai/gpt-oss-120b, openai/gpt-oss-20b and qwen/qwen3.8-27b are 30 requests per minute, 1,000 requests per day, 8,000 tokens per minute and 200,000 tokens per day. The page has Free and Developer tabs and the fetch could not tell which plan the table belongs to. [Groq rate limits](https://console.groq.com/docs/rate-limits)
- GitHub Models: "As of July 30, 2026, GitHub Models has been fully retired." Playground, catalogue and inference API are no longer available; GitHub points to Azure AI Foundry. [GitHub Docs](https://docs.github.com/en/github-models/use-github-models/prototyping-with-ai-models)
- OpenRouter free models: 20 requests per minute; 50 per day below 10 credits purchased, 1,000 per day at or above. [OpenRouter limits reference](https://openrouter.ai/docs/api/reference/limits)
- Abuse of open LLM endpoints is catalogued by OWASP as LLM10:2025 Unbounded Consumption ("denial of wallet"). Guidance collected from Cloudflare community threads and project issue trackers: per-IP limits alone are weak because abusers rotate proxies; the Workers rate-limiting binding is counted per Cloudflare location and is approximate; the free plan allows one rate-limiting rule; checks must run before the model call in this order: Turnstile or auth, input size limit, per-user or per-IP allowance, global daily cap; set a hard spend cap at the provider as the backstop. [Cloudflare community thread](https://community.cloudflare.com/t/protect-worker-from-abuse-using-turnstile-captcha/877341); [AppScale blog on denial of wallet](https://appscale.blog/en/blog/denial-of-wallet-llm-cost-exhaustion-attack-defence-architecture-2026); [example project issue](https://github.com/PedroDnT/SILO-BZ/issues/892); [classmethod rate-limit experiments](https://dev.classmethod.jp/en/articles/cloudflare-rate-limit-experiments/) (search-result summaries)
- A reported real case: an unauthenticated AI translation endpoint was turned into a free general-purpose LLM by prompt injection. [DEV write-up](https://dev.to/najmedine_salem_0e28e0e35/prompt-injection-missing-authentication-how-i-turned-an-ai-translation-api-into-a-free-llm-abuse-2194) (title and summary only)

### Inferences
- Minimal proxy design (NEEDS SERVER, though only a serverless function and no accounts): one Cloudflare Worker that (1) accepts only the site's origin, (2) verifies a Turnstile token, (3) rejects bodies over about 1 KB of user text, (4) keeps a per-IP daily counter and a global daily counter in KV or a Durable Object, (5) builds the full prompt itself from a fixed template so the caller supplies only the sentence and the current device JSON, (6) calls the model with a schema-constrained response and a low output cap, (7) returns only JSON that passes schema validation. Steps 5 to 7 are what stop the endpoint being useful as a general chatbot: an attacker gets back nothing but a device settings object.
- Using Workers AI as the model keeps the worst case at zero dollars on the free plan: when the 10,000 daily neurons run out the feature stops until midnight UTC instead of producing a bill. At the estimate of 2,500 input and 800 output tokens on llama-3.1-8b-fast, one request is about $0.00042, which is about 38 neurons at $0.011 per 1,000, so roughly 260 requests a day fit in the free allocation (my arithmetic from Cloudflare's listed prices; verify against the neuron table).
- Groq's 200,000 tokens per day would cover about 60 requests a day at 3,300 tokens each, if that table applies to the free plan.
- A Gemini free-tier key gives far better models than Workers AI at zero cost, but the limits are per project and unpublished, a single abuser can exhaust the day for everyone, and user text is used by Google for product improvement, which should be disclosed.
- Running even this small proxy changes the project's character: there is now a secret to protect, an endpoint to monitor and terms of service to comply with. If the owner's reluctance about a server is firm, the user-side options in sections 1 to 3 and the non-LLM route in section 6 avoid it completely.

### Gaps
- Gemini free-tier requests-per-day figures for late 2026 could not be confirmed from a primary source; they are only visible inside AI Studio.
- Whether each provider's free-tier terms allow serving anonymous public users through a shared key was not checked for any provider. This matters and should be read before building a proxy.
- Groq's exact free-plan limits were not separated from the Developer plan.
- Whether Workers AI supports JSON-schema-constrained output on the listed small models was not confirmed from the pricing page.
- Whether blocked requests count toward the Workers free plan's 100,000 requests per day is reported as an open question in one source.

## 6. Non-LLM alternatives for "describe a sound"

### Takeaway
An established synth maker shipped text-to-patch in 2026 without any LLM: Sonic Charge's PhenoType for Synplant 2 runs locally using a text parser and a tag-based neural network, and was received as limited but inspiring. Tag matching, a tiny in-browser embedding model, randomise-with-amount and breeding are all fully static-site compatible and cost nothing per use.

### Cited Findings
- Synplant 2 PhenoType (MusicRadar, 2026-06-10): type a description, press a button, get a patch plus a generated description and a confidence score; a random-prompt button suggests ideas; if the parser does not understand, it generates a random patch. It runs locally with no internet connection, is not built on a large language model and is not marketed as AI; it is "an algorithmic text parser and a specialized neural network" working with hundreds of internal tags and their synonyms. Free for Synplant 2 owners; Synplant 2 is €149 with a free trial. Reviewer: handled simple prompts well, mixed on complex ones, simple natural English works best, abstract descriptions are beyond it, yet results were "creatively inspiring and highly usable sounds". [MusicRadar](https://www.musicradar.com/music-tech/is-synplant-2s-new-prompt-based-patch-generator-the-future-of-synthesis)
- Synplant 2 Genopatch: local machine learning that takes any audio sample and breeds four lines of candidate patches that approximate it; its developer describes it as a combination of machine-learning algorithms tuned over about 10 years and deliberately keeps confidence low so it starts with "pretty wild guesses". Launch pricing $149, $50 upgrade. Reviewers contrasted its local processing favourably with cloud AI tools. [CDM hands-on, October 2023](https://cdm.link/2023/10/synplant-2-hands-on/); [CDM: the road to Synplant 2](https://cdm.link/2023/10/the-road-to-synplant-2/)
- Randomisers and mutators in forum discussion: users value control over the amount and scope of randomness (Access Virus is cited); Absynth's Mutator is called the best randomiser "in terms of useable outcomes"; the Nord G2 mutator is praised for combining randomising, morphing and evolution; results are seen as starting points that become useful with a little editing; randomisers that only produce noise are dismissed; a morphing device was criticised for not interpolating all parameters. [KVR: Mutate and Random and Preset-Morph](https://www.kvraudio.com/forum/viewtopic.php?t=415311); [KVR: synths that randomise](https://www.kvraudio.com/forum/viewtopic.php?t=565834); [Gearspace thread](https://gearspace.com/board/electronic-music-instruments-and-electronic-music-production/1272413-synths-patch-randomization-algorithms.html); [lines forum: synths that morph presets](https://llllllll.co/t/synths-that-can-morph-presets-settings/47663) (search-result summaries of forum threads, several of them old)
- Small embedding models run in the browser through Transformers.js: all-MiniLM-L6-v2 has 22M parameters and a quantised download of roughly 23 MB (secondary-source estimate), with peak memory of 150 to 300 MB reported on one machine. [SitePoint](https://www.sitepoint.com/optimizing-transformers-js-production/); [HF benchmark Space](https://huggingface.co/spaces/Xenova/webgpu-embedding-benchmark/discussions/3)
- Output Co-Producer: a free text-prompt Pack Generator returns four ideas; the paid part is a DAW plugin that analyses the track to find matching samples, with a seven-day trial then monthly or annual billing. Pricing checked by the source on 2026-08-29; Output calls the generator free "for now". [The Rundown tool page](https://www.therundown.ai/tools/output-co-producer) (secondary source)

### Inferences
- PhenoType is the closest precedent to what Plugin Playground needs: a fixed vocabulary of sound words mapped to parameter moves, a fallback to random when nothing matches, and a confidence readout. With only 7 effect modules and a handful of dials each, a hand-written table (for example "warm" lowers a filter cutoff and adds saturation; "wobbly" raises modulation depth; "huge" raises reverb size and mix) is a few hundred lines of data, runs instantly, works offline and can be tested deterministically.
- A layered design costs nothing per use: (1) keyword and synonym table adjusts dials; (2) embedding search over a library of described presets (precomputed vectors shipped as a small file, query embedded in the browser with a roughly 23 MB model) picks the nearest starting preset; (3) "variations" produces 4 neighbours by jittering dials within their ranges by a user-set amount; (4) "breed" interpolates between two liked results. Because a device is a small JSON of numbers and enums, interpolation and mutation are trivial and every result is valid by construction.
- The forum evidence says the features users keep are the ones with an amount control and mostly usable results, which argues for jittering around a good preset inside known ranges and not for fully random devices.
- This route also serves as the universal fallback under any LLM option, since every LLM path in sections 1 to 5 is unavailable to some visitors.

### Gaps
- No sales, usage or satisfaction data for PhenoType, Genopatch or any randomise feature was found; reception evidence is one review and forum opinion.
- No reviews specific to Vital, Pigments or Serum 2 randomisers were retrieved.
- No AI or text-prompt preset generator from Waves or Arturia was found; one search returned nothing for either. Vochlea was not researched. Treat all three as unconfirmed, not as "does not exist".
- The exact download size of a current small embedding model should be checked on its model card.

### Inferences
- Every hosted competitor pays for heavy work per request (a large model writing C++ plus a compile farm), which is why they charge $10 to $30 a month and meter free use at 2 to 20 requests. Plugin Playground's AI step is a single small JSON completion costing a fraction of a cent, with everything after it deterministic and local. That makes "free, no account" a position the hosted products cannot match on cost structure.
- The free competitors show that this audience tolerates "bring your own AI", including the crude copy-and-paste version, when the tool itself is free.
- No product in this set publishes a marketplace commission; two say they take no share of sales, and the one launched marketplace was empty at launch. There is no evidence here that a marketplace is a working revenue source for anyone yet.
- The most quoted complaint about the paid product is that there is no way to hear a result before paying. A free site where the result plays immediately in the browser answers that directly.
